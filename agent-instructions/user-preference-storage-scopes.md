# User Preference Storage Scopes

Before adding or moving an app preference, classify it into exactly one of these scopes and use the canonical path builders instead of hardcoding a drive, server root, project folder, or Windows login:

1. **Local-user preference:** Settings that follow only the current Windows user on the current PC belong under `%APPDATA%\ArcRho`. Root files such as `workspace_paths.json` and `local_project_prefs.json`, JSON files under `%APPDATA%\ArcRho\prefs`, and cache-like preferences under `%APPDATA%\ArcRho\cache` are all local-user state. Standalone Arcode uses `%APPDATA%\Arcode` for mode-specific local state, including `user_settings.json`. Browser `localStorage` is also local-user state, but Electron manages its physical profile files; application code should address it by storage key rather than filesystem path. The current keys of that kind are the colour theme (`arcrho_color_theme`, owned by `frontend/ui/shared/services/color_theme.js`) and the default tab each kind of nested window opens on (`arcrho_default_window_tabs`, owned by `frontend/ui/shared/tabs/window_tab_catalog.js`), both of which apply in every project. The canonical Python owner for ArcRho/Arcode AppData selection and local preference paths is `frontend/app_server/config.py`, which delegates the `%APPDATA%\ArcRho` folder, the `workspace_paths.json` file name, and ArcRho Server root resolution to `python-api/src/arcrho_api/config.py` so macros and the desktop app never disagree; Electron-owned JSON preference paths are built in `frontend/electron/main.js`.
2. **Project-user-specific preference:** Settings that must follow one Windows user within one ArcRho project belong at `<workspace_root>\<projects_dir>\<project>\users\<encoded-windows-login>\preferences.json`. Resolve `workspace_root` and `projects_dir` from the local `workspace_paths.json`, resolve the actual project directory through app-server config helpers, and obtain/encode the login through the shared user-identity and filename-encoding helpers. The canonical path owner is `frontend/app_server/services/project_user_preferences_service.py`; do not construct this path independently in consumers.
3. **Server-shared preference:** Settings shared by all users and projects using the configured ArcRho Server belong under `<workspace_root>\config\<preference-file>.json`. Resolve `<workspace_root>` from `%APPDATA%\ArcRho\workspace_paths.json`; never assume `E:\Arco Server`. The current shared dataset number-format preference is `<workspace_root>\config\dataset_number_formats.json`, canonically resolved by `frontend/app_server/config.py::get_dataset_number_formats_path()` and optionally overridden by `ARCRHO_DATASET_NUMBER_FORMATS_PATH`. The shared SQL Server import history is `<workspace_root>\config\mssql_connections.json`, canonically resolved by `frontend/app_server/config.py::get_mssql_connections_path()` with its filename and payload schema owned by `arcrho_api/source_table_contract.py`; it records server/database identifiers and a last-used timestamp only and must never hold credentials. New server-shared preferences must likewise have one canonical filename/path builder in app-server config.

**What a second app window can remember** (measured 2026-09-30 with two dev apps on one Electron profile, one theme change and one probe key written in each, both closed through the normal close path, then reopened). Two apps of one profile share one Chromium storage folder, but only the first app to start holds it; the second keeps its browser `localStorage` in memory, sees none of the first app's writes, and loses everything it writes when it closes. The first app's writes reach disk, but only under the origin of the port it ran on, so they come back only when a later app runs on that same port; an app that starts on a free port because the usual one is busy opens with empty browser storage. The colour theme and table style survive from either window anyway, because the Electron host also writes them to `%APPDATA%\ArcRho\prefs\main_window_prefs.json` (merged per key, last writer wins) and passes them to the page at load. Keys held only in `localStorage`, such as `arcrho_default_window_tabs` and `arcrho.notes.font-size`, are lost when set from a second app window. Nothing was moved; moving those keys to a host file is a separate plan.

Local-user preferences stay with one PC profile, project-user preferences follow the project and encoded Windows user, and server-shared preferences affect every user of that configured server. Do not use local AppData for a preference that must be shared, and do not use a server-shared file for user-specific state.
