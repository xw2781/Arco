Prototype of the Import Data window when a project's source is built from several tables. The example rebuilds the ResQ Channel table from Arco - Merge Tables.ipynb: three SQL Server tables and one CSV, matched on seven keys. Click a table card to see where it comes from and set its nickname. Try the key cells, the join pills, and the column lists too.

How it fits

Table 1 · SQLTable 2 · CSVTable n →Combine (keys, row rules, columns) →source/master_table.csv →Field mapping · dataset types · reserving classes · Engine refresh (unchanged)

Everything after the import already reads one file, the project's master table. A combined source writes that same file, so no downstream code changes.

The join model

  • One base table. The first table in the list. Every other table joins onto the result in list order. Drag to change it.
  • One shared key set. Keys come from the base table's columns. Arco matches them in other tables ignoring case, spaces and underscores, so Co_Cd lines up with CO_CD on its own.
  • A missing key is filled with a fixed value (the notebook's sys_yrmo = 0) or matches any value. Matching any value repeats that table's rows, and the window warns about it.
  • Row rule per table: All Rows (outer), Base Rows (left), or Matches Only (inner). All Rows is the default, as in the notebook.
  • Nicknames: each table can have a short nickname, asked for when it is added. The map and messages show it in place of the table name.
  • Columns: click a column in a table's list to leave it out or rename it. A name clash gets the table's nickname as a suffix until you rename it.
  • Clean-up is automatic: empty Unnamed: n columns and blank rows are dropped, as read_csv_clean does.

Import window

  1. Source. With one table it is today's form, field for field. Add Table turns it into a list. SQL tables are grouped under their connection, so the server and database are entered once.
  2. Table details. Paths, server, database and the column list sit in a small window opened from any table row or card, so the main view stays short.
  3. Combine. Appears only with two or more tables. The Join Map and the Row Match check live here. Problems show before anything is written.
  4. Datasets and Reserving Classes: unchanged.

Import Again re-reads every table and repeats the same combine. Change Source reopens step 1 with the list.

Server side

  • Read each table into source/parts/<id>.csv: copy a CSV, stream a SQL table, exactly as single imports do now.
  • Combine as text. Read every part with all columns as strings, so keys compare exactly and no number is reformatted on the way through.
  • Write once. The combined result goes to a staging file and replaces master_table.csv in one step, like today.
  • Preview endpoint. Step 2 asks the server for row counts, match counts, warnings and the first rows, read from the key columns only.
  • Contract. The JSON change follows the dataset contract process; single-table projects keep their current record.

Open questions

  • Monthly paths. Each month's files carry the month in the name. Should a path accept a token such as {YYYYMM} filled from Development End?
  • Stacking. Should a second mode append tables with the same columns (union) as well as join them?
  • Different keys per pair. Left out: the notebook never needs it, and one key set keeps the map readable.
