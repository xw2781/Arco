# Frontend: Dfm

## Purpose
<!-- MANUAL:BEGIN -->
DFM feature across Details, Data, Ratios, Curves, Results, Notes, Links, and Audit Log on top of dataset context, with method metadata in Details. Links follows Notes.
DFM Notes reuses `ui/shared/tabs/notes/` for path highlighting, `Tab`/`Shift+Tab` indentation, `Esc` to exit editing, spellcheck off, and whole-note display formatting while preserving DFM's `dfm_persistence.js` save flow. File paths render as deep-blue underlined non-bold text, known file extensions stop the token before trailing prose, and right-click shows `Open File`, `Copy File Path`, plus `Open as Read-Only` for Excel workbooks; focused editing shows plain text until focus leaves the textarea and toolbar. DFM relays nested `arcrho:open-path` requests to its parent so Notes links keep working in popped-out tab surfaces.
<!-- MANUAL:END -->

## Interactive Guide
<!-- MANUAL:BEGIN -->
The question-mark SVG button at the top right toggles an interactive guide for all eight tabs. Guide mode outlines the available components and adds numbered help markers directly on the page. Hover a component or focus/click its marker to read one contextual tooltip at a time. Each tooltip contains one short summary and at most four action bullets. The toggle centers a question mark with a rounded stroke and solid dot inside a circular frame; its zero padding overrides the shared text-button padding.

Contextual hints explain hidden gestures and right-click entry points: development-header double-click for the ratio chart; distinct ratio, average-row, average-value and selected-pattern menus; user-column editing on Curves; table actions on Data and Results; file actions in Notes; and workbook actions in Links. Origin-row hints hold exclusion shortcuts. The active tab's marker explains right-click pop-out/dock behavior.

The guide has no side panel and does not resize the working page. Tooltips stay within the viewport; markers follow scrolling, resizing and table re-renders. Ordinary clicks dismiss the tooltip so the underlying controls and menus remain usable. The button or Escape removes all guidance, returning focus to the toggle when a marker had focus. Guide state belongs only to this open window, starts off, and never changes method data, dirty state, save payloads, or audit history.

`dfm_guide_content.js` owns the copy and target selectors; `dfm_guide.js` owns the interaction and reuses the shared tooltip surface. Run `frontend/node-portable/node.exe frontend/tests/dfm_guide.e2e.cjs` from the repository root for isolated Electron GUI checks against the real page and synthetic triangle data.
<!-- MANUAL:END -->

## N/A Cell Borders
<!-- MANUAL:BEGIN -->
Ratios always draws the normal grid borders on N/A cells, with the shared table frame owning the outer edges. There is no hide/show action or runtime preference; a previously stored local border preference has no effect.
<!-- MANUAL:END -->

The tail cell carries the pale cyan User Entry fill on every row. A User Entry row's tail is one of its formula cells; any other row's tail takes a typed number through the formula bar (select the cell, type `=` or edit the bar, Enter), and plain arithmetic is accepted, but a row, dataset or workbook reference is refused with "Enter a tail factor greater than zero." because nothing recalculates that cell. - DFM Curves tab (`dfm_curves_tab.js`, the ArcRho counterpart of ResQ's Curves | Data tab) sits between Ratios and Results. Its grid shows the Initial Selection (the Ratios tab's selected factor per period and its tail), an Include column, the Exponential Decay, Inverse Power, Power and Weibull curves fitted by log regression to the included factors, any user value columns, and then the Selected Estimate Number, Selected Value, Cumulative Value, Cumulative Percentage and Incremental Percentage. Below the periods come the tail row (`<age> - Ult`), the Fit / A / B / C / R-squared % rows, and the Tail Pattern block, opened by a quiet rule and headed by the Tail Pattern row whose X marks the column the tail runs off along, followed by one row per Future Dev. Period. That column carries the same green fill through every future period row, so the choice and the run-off it produces read as one block, and clicking a future period cell picks its column exactly as clicking the X row does; the X and the fill name the column the figures were built from (`selected_tail_pattern_column`) rather than the stored setting, so a setting pointing at a removed column shows the column actually used. The toolbar holds Fitting Method (Log Regression; a method imported from ResQ with Least Squares keeps that setting, shows a notice, and is still fitted by log regression), a disabled Weighting selector, the Future Dev. Periods stepper, and Free Fit C. The Curves and Results toolbars are the same control bar: both carry `dfmPageControls`, which owns the bar, its labels and its stepper fields once, so a control added to either sits in the same box. Every scrolling area of the DFM page carries `dfmScrollArea`, which owns the 20px tray, the quiet thumb and the single step arrow per tray end, so the Curves grid scrolls like Details, Ratios and Results; the Curves grid frame closes on its left and top edges and takes the same focus ring as the Results frame. Each is one undo step, and `Enter` on a formula already selected for its column changes nothing rather than marking the method dirty. The marker survives a Ratios re-render because it is kept as a position rather than on the cell, and a triangle cell takes it even where there is no ratio to exclude, so the arrow keys carry on from wherever the pointer left off. The view-only Show Data command interleaves the current Data-tab observed values before their corresponding ratio columns; average-formula and selected/cumulative rows receive blank data-column spacers so all logical ratio columns remain aligned. Toggling Show Data does not change ratio indices, formulas, saved method JSON, or dirty state. Edit-mode summary-cell actions do not apply that temporary label emphasis. Shift/Ctrl-drag highlights Ratios cells in Edit mode without replacing the existing strike-toggle drag gesture. Existing selected-ratio/selected-formula fills are preserved.

- When loading DFM JSON from RPC/local method payloads, DFM reconstructs runtime average formula rows from the `average formulas` object. Supported inferred labels are `Volume - all`, `Volume - <n>`, `Simple - all`, `Simple - <n>`, and the same labels with `Ex hi/lo` or `Ex hi/lo x<n>` suffixes; unresolved labels are skipped.
- DFM template files use `.arc-dfm` extension only (`DFM_Template@<Project>@<ReservingClass>.arc-dfm`); legacy `.arcdfm` suffix is not accepted.
- After required Details inputs are all populated, DFM checks whether the instance JSON exists at the standard local save path; if missing, it does not show the former inline warning/`Confirm` action beside `Name` (new-object guidance is status-bar only).
- On the same local instance-file lookup, once DFM Details has committed values for `Project`, `Reserving Class`, and `Name`, DFM automatically checks for a matching local method JSON. If found, it auto-loads the file and reports the loaded file path in the status bar. If not found, it reports a yellow status-bar warning (via shell status `tone=warn`) with the exact text `This method object has not been created yet, changes will be saved to a new container.` The lookup does not wait for `Input Triangle` / `Output Vector` / period lengths.
- Details `Input Triangle`, `Origin Length`, and `Development Length` are saved properties of the current DFM instance, not local instance lookup keys; changing them marks the current DFM dirty and follows the normal dataset refresh behavior without reloading method JSON from disk. Saving the DFM object writes the adjusted length values back into the stored method JSON.
- DFM Details `Name` is a plain text input with a project/path-scoped selector backed by the Reserving Class folder's `index.json`; it does not use the older browser-local saved-name dropdown or delete action.
- Temporary debug aid: DFM local-method lookup currently emits short status-bar debug messages (for trigger/skip/checking-path) prefixed with `Debug: DFM local method lookup ...` to help verify the frontend lookup flow during Details input changes.
- DFM local-method lookup scheduling is debounced and reason-coalesced; higher-priority `details-change` lookups are not downgraded by later `tab-activated` triggers (avoids false `dirty + tab-activated` skips immediately after Details edits).
- Shell tab activation/state-request messages refresh DFM edit-state reporting only; they do not trigger local method lookup.
- Existence checks run on committed input changes (`change`/selection/blur`) rather than every typing keystroke.
- DFM responds to shell `arcrho:assistant-context-request` messages with the active DFM tab, Details field values, dirty state, standard method JSON path, and current in-memory method payload so ArcBot can analyze the active method even when host-side direct reads from the server share are denied. ArcBot edits arrive as `arcrho:assistant-apply-json-edit`: the DFM checks the edit is for its own method path, applies it through the owned-patch apply as one whole-method undo step, and saves through its normal hosted save (a failed save leaves the edit as unsaved changes). `arcrho:assistant-revert-json-edit` undoes that step and saves again, and is refused when the latest undo step is not ArcBot's.
- DFM watches the active local method JSON file for external disk changes. When the page is clean, a changed JSON file is reloaded into the active GUI automatically; changed Ratios exclusion cells and Average Formula selection cells briefly flash blue so API/ArcBot edits are easy to inspect. When the page is dirty, DFM does not overwrite in-memory edits and posts a warning so the user can save or reload deliberately.
- A DFM save runs behind the shared saving animation described in [`dataset.md`](dataset.md), titled `Saving DFM Method`, so the page cannot be edited while the save settles. `saveRatioSelectionPattern` wraps the save in it, so it covers every save entry point: the Save bar, the shell `arcrho:dfm-save` and `arcrho:dfm-save-as` messages, and Excel bridge saves. The card streams the dependent walk's live updates before the spinner is dismissed, which still happens before the post-save review warning and at the start of the save error path so no dialog opens behind it. No save closes the window. The explicit Save command (Save bar button and the shell `arcrho:dfm-save` message, which routes through the same bar handler and its in-flight guard) shows the saved-dependents notice after a clean walk (`propagationClean`) and leaves the method open; Save As and Excel bridge saves show no notice, and a failed or stalled walk shows none either.
