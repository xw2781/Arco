# Frontend: Project Instance

## Purpose
<!-- MANUAL:BEGIN -->
- Help ? Open Dataset JSON File and Open Dataset Sidecar open a read-only Arcode preview loaded through the Gateway by project/class/file identity. These menu actions do not open or save a share path. General Arcode file editing remains available when a user explicitly opens a file.
Project instance workspace for browsing one project's reserving-class paths and dataset types.
Only manual/input datasets have editable values in the Dataset Viewer. Calculated, engine-generated, and method-output datasets allow display settings and notes to be saved while their grid and links remain read-only; formulas belong in Project Settings and derived values refresh through their inputs or methods. Normal table opens leave source-based editing eligibility to the shared Data tab. Temporary views alone set the window-wide read-only launch flag.
<!-- MANUAL:END -->

## External Interfaces
<!-- MANUAL:BEGIN -->
- Opened by shell as a `project_instance` iframe tab after Project Settings posts `arcrho:open-project-instance`.
- Calls shared dataset-types and reserving-class picker helpers.
- Embeds the same lazy reserving-class picker body used by Dataset/DFM/Workflow, so the project instance left panel loads the same hierarchy, filters, hidden-path preferences, Shortcut section, favorites, and user-defined favorite folders.
- The embedded reserving-class path tree uses tight horizontal padding with a small left inset and does not reserve two-sided scrollbar gutters, so more path text fits in the left panel. Tree rows keep their depth-based left indentation and fit the panel width: favorite-star actions in Shortcut and All Paths stay anchored on one right-edge vertical line at any panel width, and the last icon button in each of those two section headers ends on that same line, so the header buttons and the stars beneath them read as one lane (the header button is 20px around its 14px glyph while the star is 18px, so the header button ends 3px in from the header edge where the star ends 4px in from the row edge), as soon as one visible row's level tag no longer fits beside its label every level tag is hidden together (whole, never cut mid-word) and they all return when the panel widens, and a label that reaches the star runs underneath it, where the star sits on a strip of the row's own background. Hovering a tree or Shortcut label shows its full path in a compact app-styled tooltip that wraps within the viewport instead of using the browser-native tooltip.
- Settings files. Two panels can write part of their own state to a JSON file the user keeps and read it back, both through `ui/shared/components/settings_file/settings_file.js`, which owns the file envelope, the desktop save and open dialogs, the drop zone with its dashed hint, and the two-item right-click menu. Every file carries a `kind` naming the panel that wrote it, so one panel refuses another's file, and each panel marks its root `data-file-drop-zone`, which is how the shell's window-wide scripting-file drop knows to leave these drops alone. Neither panel spends toolbar or header space on a button: the right-click menu carries both actions and a drag carries the load, so the visible chrome is unchanged by the feature.
- Right-clicking the Shortcut section header, or clicking its config-file button to the right of Add Favorite Folder, offers Save Shortcut and Load Shortcut, the second through the open dialog; dropping such a file anywhere on the path tree panel loads it too. Below a divider the menu lists up to three shortcut config files this user saved or loaded most recently as `Load "<file name>"`, newest first, with the full path in a tooltip to the item's right; choosing one loads that file without the dialog. Loading replaces the current shortcuts outright when they match one of those recent files (same paths, nicknames, and folders); otherwise it first asks "Save the current shortcut settings first?" with `Save` and `Discard`, where Save writes them through the save dialog, and closing the box or canceling the save stops the load. Only the paths are remembered, per kind of settings file, in the local-user file `%APPDATA%\ArcRho\prefs\recent_settings_files.json` through the host's `recent-settings-files-preferences-load`/`-save` channels; the recent list, the tooltip, and the save-first check (`confirmSaveBeforeLoad`) are owned by `ui/shared/components/settings_file/settings_file.js` and shared with the dataset toolbar menu below. It carries the section's favorite paths, nicknames, and favorite folders. Loading keeps only the paths the current project has and reports how many were loaded and how many were left out; the result persists through the same project-user tree preferences the star and folder actions use.
- Right-clicking the dataset toolbar offers Save Group And Filter and Load Group And Filter, and dropping such a file anywhere on the right panel loads it. The same recent-files section as the Shortcut menu follows a divider, with up to three group and filter files. It carries the table's grouping and column filters. Loading replaces the current grouping and filters outright when there are none or when they match one of the recent files (same filtered columns and values, same grouping order); otherwise it first asks "Save the current group and filter settings first?" with `Save` and `Discard`, as the Shortcut load does. A load clears collapsed groups and reports what it applied. Columns the table does not have are dropped on load and a filter value a column no longer offers prunes itself on the next render. The same two fields are the ones the stored table preferences carry, built and applied by one pair of functions in `project_instance_dataset_table.js`, so a file and the preference store cannot describe the same view differently.
- Project instance loading shows one centered page-level loading card with the same blue sweep spinner style used by Dataset loading while the reserving-class path tree and dataset table load.
- The path-tree load issues its requests concurrently rather than in sequence, because project data may sit on a mapped drive where every serialized request costs a full round trip. The picker starts the saved filter-spec request alongside the combinations and types pair instead of waiting for them, and the shared project-user preference loader joins an already in-flight request so the path panel and the dataset table, which both load preferences as the page opens, share one read instead of making two. A forced reload still issues its own request, and a failed load is not cached.
- Embeds the existing Dataset Viewer page in draggable in-tab windows.
- Double-clicking a dataset that already has an open or hidden floating window activates or restores the existing window instead of creating a duplicate for the same selected path and dataset.
- New floating dataset windows default to about 80% of the project-instance frame and reuse the most recent floating dataset window size for subsequent dataset windows in the same project instance page.
- Floating Dataset, DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod window titlebars highlight the active top window. Titlebars show only the dataset/method name when the window belongs to the currently selected reserving-class path, and fall back to the full reserving-class path plus dataset/method name when the left-panel selection moves to a different path; hovering the titlebar text does not show a native browser tooltip. Minimized toolbar tabs use the dataset/method name without method-type prefixes.
- Floating dataset window titlebars include shell-matching minimize, maximize/restore, and close icon buttons; clicking the minimize button or right-clicking the titlebar sends the window into the toolbar hidden-tab strip.
- Dataset viewer windows follow the shell's existing Windows 11 frame flag, using rounded frame corners on Windows 11 and square corners otherwise.
- Dataset viewer windows can be resized from all corners and edges, with the southeast handle using the same dotted resize glyph as the main shell and shell floating tabs.
- Double-clicking a floating dataset window titlebar toggles maximize/restore within the project-instance frame; dragging a maximized titlebar restores the prior size under the pointer before moving.
- Dataset viewer windows are clamped below the project-instance toolbar; they may be dragged partially off the left, right, or bottom edge as long as a side grab area and the titlebar remain reachable.
- `Ctrl+W` closes the active floating dataset window, including when keyboard focus is inside the embedded Dataset Viewer iframe or when the shell/Electron close-tab shortcut reaches the parent shell first; the project instance tab closes only when no floating dataset window can consume the shortcut.
- `Ctrl+PageUp` and `Ctrl+PageDown` are forwarded to the active floating Dataset or method window when Project Instance owns keyboard focus; once focus is inside the child iframe, its shared tab runtime handles the same shortcut directly.
- The toolbar includes a hidden-tab collection area to the right of the selected path; hidden windows appear as large-radius minimized tabs on the toolbar that show dataset names only plus a styled hover tooltip with the full window title. Each minimized tab uses a centered inline SVG close icon, and hovering or clicking the hidden-tabs button opens a wider content-fitting dropdown that lists full hidden window titles with a one-second hover grace period, per-item close controls, Resume all tabs, Close all tabs, a centered inline SVG close icon that dismisses the dropdown itself, and a matching restore animation that starts from the matching minimized tab. The hidden-tabs button and its dropdown are hidden entirely while no window is hidden, so the toolbar never shows a `0 hidden` control or an empty-state menu.
- Right-clicking anywhere in that hidden-tab collection area — including the empty stretch of toolbar it keeps while nothing is minimized — opens a `pi-table-context-menu` that acts on every nested window at once: `Restore windows` restores each minimized window to its remembered rectangle, `Minimize all` docks every visible window to the bar in one pass, and `Close all windows` closes the windows that are not dirty and leaves any window with unsaved changes open, reporting in the status line how many stayed. The menu preserves the dirty-state close confirmation by never closing a dirty window rather than by prompting in bulk. Each item is disabled, not hidden, while it has nothing to act on, and opening the menu dismisses the hidden-tabs dropdown and the minimized-tab tooltip.
- Dataset viewer windows move and resize through Pointer Events captured on the titlebar or resize handle (`arcrho-ui-design` L16), so a fast drag across an embedded iframe or past the app edge never loses the window; a transparent parent-page drag shield still shows the move or resize cursor for the whole gesture. The frame is sized border-box, so the size a move reads back is the size it writes and the window keeps its dimensions from one drag to the next.
- The project instance toolbar is compact, shows only the currently selected reserving-class path, omits the duplicate selected path above the tree, and sizes the path label to its content with a capped width so minimized toolbar tabs get the remaining space.
- The selected reserving-class path in the toolbar is interactive: each level renders as a compact rounded segment, and clicking a segment opens a small styled picker below it with alternate values for that level from the shared reserving-class hierarchy. The picker focuses a type-to-search field that filters the loaded values without reloading the hierarchy; Arrow keys move between the search field and visible results, and Enter chooses the sole matching value. Choosing a value preserves the existing lower-level suffix when that branch exists, otherwise it selects the first valid descendant path. Right-clicking anywhere on the path highlights the full path and opens Copy/Paste actions. Paste accepts only a valid leaf path from the loaded reserving-class hierarchy, selects that canonical path, collapses the old divergent branch, expands the pasted path, keeps its selected-row highlight visible, and scrolls it into view.
- The left and right panel title bars are omitted so the reserving-class tree and dataset table start directly below the toolbar. The embedded reserving-class tree starts from the full project path hierarchy instead of applying a previously saved reserving-class picker filter; the All Paths header exposes a Collapse Bottom Level control before the Hidden Paths, Filter, and Preferences controls. It collapses the deepest currently expanded folder level in one click, while the remaining controls let users intentionally narrow or configure the tree in place. The Filter window's `Hide paths with no data` checkbox keeps only reserving classes whose folder holds a dataset index, plus the branches above them. The list comes from the hosted `reserving_classes_with_data` read (`GET /reserving_class_paths_with_data`), fetched when the tree opens with the option on and again when it is switched on. The choice is saved per user and project as the tree preference `hide_paths_without_data`, lights the Filter button like a level filter, and `Clear` turns it off. The tree does not re-check while it stays open, so a class that gains its first dataset appears the next time the tree loads.
- The dataset table has a compact transparent toolbar above the scroll area. Its default Normal view is driven by cached dataset instances from the selected reserving-class path: `Name` is the instance name, `Dataset Type Name` is the stored dataset type, `Category` is the indexed `dataset_category` and otherwise the `Category` that Dataset Types defines for that dataset type, and multiple instance names can share the same dataset type. The cached dataset count in the toolbar reflects visible instance rows after table filters, while the refresh button sits on the right side of the toolbar.
- The toolbar also has a Temporary view icon with a styled hover/focus tooltip that explicitly states whether Temporary view is enabled or disabled and describes only the active mode. Temporary view lists every Dataset Type marked `Generated`, whether or not it has been created for the selected path. Its Status column uses a green check when the dataset is already listed in the selected-path `index.json` and a gray check when it is not. Type-derived fields remain available; cache-only metadata such as Method Type, Last Modified, Created, and User is blank. Temporary rows can only be opened in a read-only Dataset Viewer window. A gray-status row's context menu also provides `Make Permanent`, which runs the same canonical generated-dataset flow as Add Dataset to create the CSV cache and sidecar before rebuilding `index.json`.
- Normal table column filters, except for the icon-only `Status` column, show in a framed `Filter:` section in the dataset toolbar. When no filters are active it reads `Filter: None`; active filters appear as compact column-name chips, and hovering or clicking a chip opens the same filter dropdown used by the active table-header filter button so users can review or change the selected values. Every filter menu includes a Type to search field that narrows only its displayed values; `All` still selects the full column's values. Dragging a table column header or grouped-column chip into the filter frame adds that column as a neutral `All` filter chip and opens its filter menu. Selecting `All` keeps a neutral chip in the filter frame without the blue active-filter treatment, and dragging a filter chip out of the frame clears that column filter.
- The dataset table `Method Type` and `Status` columns, including their filter options, read method metadata from the selected reserving-class folder's cached `index.json` `files` entries, matching rows by instance `name`; datasets missing from the cache display `None` and a green updated status. `Status` shows a green check for sidecar `status: 0` and a yellow warning when a method-backed output has `status: 2`, because recalculation changed meaningful method JSON or cached values, a refresh failed, or someone marked it for review from the row context menu. Successful unchanged recalculation preserves green; existing yellow stays yellow until explicit Save. Timestamp/user/audit changes alone never require another review. The two codes are read through `ui/shared/dataset/review_status.js`, the one frontend reading of what the stored number means, shared with the method windows that keep Save available while their output is flagged. A second thing also turns the cell yellow: a linked Excel workbook that now holds numbers the object has not loaded, checked in the background for the selected class (see the Excel Link Manager section). That verdict is an observation of files no index describes, so it is never stored - it paints the column and its tooltip only, the row menu's `Mark for review` still reads the stored flag alone, and Temporary view, whose Status answers a different question, ignores it. A row flagged for both reasons carries both sentences in its tooltip.
- Double-clicking a dataset row whose `Method Type` is `DFM`, or choosing `View` from its row context menu, opens the DFM method tab by default. Rows whose `Method Type` is `Result Selection`, `Bornhuetter Ferguson`, or `Cape Cod` open that method window directly on its Method tab, and `Bootstrap` and `Stochastic Consolidation` rows open their windows on the Results tab; method routing is independent of whether the indexed output format is Vector or Triangle. The same row context menu shows `Show as vector` immediately after `View` for DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, Bootstrap, and Stochastic Consolidation vector rows, and shows `View as triangle` for triangle rows. These format-specific actions always open the saved output in a normal Dataset Viewer window without showing method details. Method-backed vectors label the single value column `Ultimate` instead of using the first development-period label. Cached dataset rows open read-only unless their indexed `source_kind` is `input`.
- The dataset table `Formula`, `Last Modified`, `Created`, and `User` columns read from the selected reserving-class folder's cached `.csv`/`.json` file metadata. `Last Modified` comes from sidecar JSON metadata such as `updated_at`/`modified` when present, with filesystem modified time only as a fallback; `Created` comes from sidecar JSON metadata such as `created_at`/`created` without using filesystem creation time; timezone-aware sidecar timestamps, including UTC `Z` values, are normalized to local display time before they are written into the cached index. A dependent propagation walk stamps the sidecar of every method or calculated dataset it rewrites, so `Last Modified` moves for every object successfully recalculated, even with unchanged values, not only for the object the user saved. Formula values come from sidecar/index metadata, and user values come from the sidecar `user`/`modified_by` Windows-login fields when present. The `Formula` column displays through the shared `formatDetailsFormulaText`, the same formatter the Project Settings Dataset Types table and the Dataset Viewer Formula field use, so one formula never reads three ways: every recognised dataset-type name is quoted whether or not the stored text quoted it, and operator spacing is normalised. The dataset-type rows the page already holds supply the names the matcher needs; without them a name containing `-` or `/`, such as `C 22 - CWOP DFM w/ Selected LDFs`, could not be told from an expression. Filtering, grouping and sorting all see the same displayed text, so a filter chip matches the cell beside it.
- The row context menu carries the review flag as a pair of items, `Mark For Review` and `Set Reviewed`, of which at most one is ever visible. They act on the whole selection at once, and only on the rows a method wrote: a selection whose `Method Type` is `None` throughout shows neither item, while a selection that mixes method outputs with plain datasets shows the item and applies it to the method outputs only. `Mark For Review` appears when every method output in the selection reads `Updated`; anything else — every row flagged, or a selection holding both states — shows `Set Reviewed` instead, so one click leaves the whole selection on the same status. The items sit after `View as triangle` and before the `Add` submenu, and they are hidden in Temporary view, which opens datasets and nothing else.
- Setting the review flag stamps the object's `Last Modified` and `User` with the moment and the person who set it, because a sign-off is a change to the object's record even though its values are untouched. It is only that: nothing downstream is marked, and no dependent propagation walk is started. An object already carrying the requested flag keeps the stamp it had, so re-running the action on a settled selection changes nothing. The page shows the shared loading overlay titled `Marking for review` or `Setting reviewed` while the request runs, then re-reads the dataset index — the sidecar writes made it stale — and suppresses the index poll for its own write so no `Refresh Table` prompt appears. That re-read rebuilds every row, so the action captures the selected rows and the table's scroll offsets before it and restores both after the redraw, exactly as the toolbar refresh does: the same rows stay highlighted and ready for the next action, and the table stays where the user was reading rather than jumping back to the top of the class. The status line reports how many objects changed, or that no change was needed.
- Dataset reloads within the same reserving-class path preserve highlighted rows and horizontal and vertical scroll offsets. Overlapping save refreshes share the state captured before loading, and only the latest load restores it; switching paths starts a fresh table selection and position.
- Adding a dataset from the cached-dataset table's add picker refreshes the cached list, highlights the newly added dataset row, and selects it in place instead of opening a floating Dataset Viewer window.
- Double-clicking a dataset table row whose `Method Type` is `DFM` opens a floating DFM window inside the Project Instance frame on its Ratios page, initialized with the current project, selected reserving-class path, and dataset name instead of opening the in-tab Dataset Viewer window or a main shell tab; it also records the selected DFM method/output name in project-user `dfmObject` preferences.
- Floating Dataset and DFM windows inside Project Instance follow the main shell corner convention: 6px by default and 8px when the page is running with the Windows 11 frame style.
- Floating Dataset and DFM windows mirror standalone save/dirty behavior: dirty-state messages show a dirty dot on the floating titlebar and minimized tab (a method page that runs a model also sends `arcrho:window-run-state`, shown as a run-state chip beside the title, and an empty label removes it), closing a dirty window asks for confirmation, confirming discard closes the floating window, and shell Save plus Ctrl+S routes to the active floating Dataset or DFM window. Saving a nested dataset or method window never closes it; the window stays open and clean so the user can keep working, and only Cancel, the titlebar close, or the close shortcut dismisses it. DFM windows also support Save As/Ctrl+Shift+S through the active floating DFM window.
- Floating DFM windows publish their active DFM state to the shell and forward standalone DFM commands, so shell Edit/Help menu actions, ratio hotkeys including the Ctrl+E Select/Edit toggle, DFM JSON opening, Notes file-link context-menu actions including popped DFM tab surfaces, and macro context/apply requests target the active Project Instance DFM window the same way they target a standalone DFM tab. Ctrl+E is forwarded even before the nested DFM iframe receives keyboard focus. When the active Ratios window is in Select mode with a highlighted range, Project Instance also forwards Enter and Arrow-key navigation with Shift/Ctrl/Cmd modifiers, including when focus is on the surrounding DFM window surface. Clicking back into the reserving-class tree or dataset table clears the active nested window and returns shell context to the Project Instance reserving-class level.
- Project Instance relays `arcrho:calculated-datasets-updated` reports between nested Dataset windows and the shell, so open nested calculated dataset windows can auto-refresh after an upstream component save.
- Project Instance relays `arcrho:dependency-source-preview` and `arcrho:dependency-source-cleared` messages between nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, Cape Cod, and Berquist Sherman windows, including DFM windows that use the shared Dataset layer. This lets a dirty upstream source feed temporary values to an open dependent method or matching Dataset Viewer window. For dirty sources that feed app-calculated Dataset Types, Project Instance also requests an in-memory calculated preview and relays the downstream calculated values, then tells dependents to reload the source from disk when the upstream source is saved, canceled, or closed without saving.
- Project Instance handles dependency open requests from nested Dataset Details pages, opening or activating the clicked dependent as a floating Dataset window using the source window's reserving-class path even if the left-panel selection has moved; method-backed Formula component chips open the related DFM, Result Selection, Bornhuetter Ferguson, or Cape Cod method window instead.
- Project Instance publishes `arcrho:project-instance-state` snapshots to the shell when the selected path or nested floating Dataset/DFM/Result Selection/Bornhuetter Ferguson/Cape Cod/Berquist Sherman windows change. Berquist Sherman snapshots use `kind: "berquist_sherman"` plus `bsTab` and `bsVariant`; the page reports tab changes with `arcrho:berquist-sherman-tab-changed`. A successful first B&S save rekeys the same floating window to the saved output Name, and restored B&S windows reopen against their own saved reserving-class path. The snapshot also includes selected path, nested window name/title, hidden/active/maximized/dirty flags, other method subtabs, and restore rectangles so Browsing History can restore Project Instance pages after Clear Cache & Reload without turning method windows into dataset viewers.
- Project Instance can host a macro review table (`ui.reviewTableOpen` with `host: "projectInstance"`, used by the Sync Reserving Class with ResQ, Import ResQ Reserving Class, and Export Reserving Class to ResQ macros) as a normal nested pi-window built from the shared `review_table` panel component. Its grid is the same `pi-table` the dataset table renders, from the same `ui/shared/styles/pi_table.css`: a colgroup carrying an explicit width per column, a sticky header cell whose label sorts on click and drags to reorder columns, a per-column value filter popover, a resize grip that double-clicks back to auto-fit, and rows the shared selection rules paint. Grouping is the one dataset-table feature it does not offer, because a review lists the actions of a single sync run, so there is no group-by strip above the table. Selection means "accept this action": a click anywhere on a row toggles its tick and highlights it, Shift-click paints the range from the anchor with the anchor's new state, and the tick column keeps its select-all for the visible rows. Because the grid uses the shared class names, the Dark sheet dresses it without rules of its own. Hovering a box walks a name too long for its line from end to end: the page measures that name's own overflow on `pointerenter` and hands the distance and a duration at a fixed 38 px/s reading pace to the stylesheet as `--dg-name-shift` and `--dg-name-duration`, which slides the name between two positions with a `transition` on `left`. The travel deliberately does not use a transform: an animating transform is promoted to its own compositing layer, and a layer inside the zoomed diagram is rasterized at the wrong scale, so the name went soft for exactly as long as it was moving while every box beside it stayed sharp; offsetting a relatively positioned box repaints it with the rest of the diagram at the zoom actually on screen, and one line of text is nothing to repaint. The turns are timed by the page rather than by keyframes, because a keyframe hold is a share of the whole animation, which would make a long name sit for many seconds and a short one barely stop: it settles for 450 ms before it first moves, so a pointer crossing a column of boxes leaves them all still, and rests 1500 ms at each end so the tail can be read before it slides back. No trip runs quicker than 1200 ms however short the travel, and only a rounded pixel of overflow is ignored, so a name hanging barely over its box still makes the trip - even 2 px of travel reveals the tail, because scrolling drops the ellipsis that was covering it. A name that fits keeps its resting ellipsis, as does every name under `prefers-reduced-motion: reduce`; a redraw or the pointer leaving stops the trip and puts the name back. ## Data/State/Caches
<!-- MANUAL:BEGIN -->
- Uses the shell-persisted project name/folder/table path as tab inputs.
- Loads the project's last selected reserving-class path from project-user preferences when the tab opens; if no last path exists, it selects the first Shortcut item when available, and otherwise the first path of the All Paths tree, expanding and scrolling the tree to it so the first visit to a project opens on a real reserving class instead of an empty page. That first tree path is the picker's own first visible leaf (`getFirstVisibleLeafPath` in `ui/shared/components/pickers/reserving_class_picker.js`), so it follows the tree's ordering and skips hidden paths; the path stays empty only when the tree itself is empty. Neither fallback is written back to preferences, so only a path the user picks becomes the project's last selected path.
- Keeps the selected reserving-class path in page memory, saves user selections back to project-user preferences, and passes it into new floating Dataset Viewer and DFM windows. Opening a floating DFM window also updates the shared project-user DFM object defaults with the selected method/output name without waiting for the DFM method to be saved.
- Saves the right-panel dataset table layout in the same project-user preferences JSON under `projectInstance.datasetTable`, including column order, manual column widths, filterable column selections, grouping fields, collapsed group rows, and sort state. Cleared/no-op filters and the non-filterable `Status` column are saved as empty arrays so stale saved filter values do not return after reload. Normal view is always the default; Temporary view is session-only and is not saved as a table preference, although its retained CSV cache persists on disk. When the current project/user has no saved `projectInstance` object yet, the preference API supplies the built-in default `projectInstance` settings before the page loads, unless `ARCRHO_PROJECT_INSTANCE_DEFAULT_PREFS_PATH` points to an override JSON. If preference loading stalls during startup, Project Instance falls back to the default table layout so the page can finish opening.
- Opening a Temporary-view dataset reuses a valid canonical cache read-only when available; otherwise it writes generated or derived CSV output to `data/<ReservingClassFolder>/datasets/.temporary-view/`. The retained temporary-view cache persists after Temporary view closes, never creates a sidecar, and never creates an `index.json` entry or triggers an index rebuild. The Temporary Status check is green when the dataset is already listed in the selected-path `index.json` and gray when it is not. Temporary windows are excluded from Project Instance restore snapshots.
- Changing the selected reserving-class path refreshes the server-side `index.json` lookup for logical cached dataset instances, stored dataset type names, minimal table metadata, and method types for the selected reserving-class data folder while preserving existing table column filters and grouping.
- Every dataset table load reads the project's Dataset Types alongside that `index.json` lookup, concurrently and under the same in-flight request guard. Dataset Types owns the `Data Format`, `Category`, and `Formula` shown for each instance, and Project Settings can add or change a type while this page stays open, so a type added after the page opened would otherwise leave its saved instances grouped under a blank `Category`. A failed dataset-type read leaves the rows already loaded in place instead of clearing the type-owned columns.
- Method type and review-status lookup are derived from the same selected-path `index.json` payload as cached dataset names and metadata, so Project Instance does not issue a second method-index request during path selection.
- Floating DFM window dirty state is tracked by DFM iframe `arcrho:dfm-dirty` messages keyed by the DFM `inst`, with iframe-source fallback during startup state sync; Project Instance sends aggregate `arcrho:project-instance-dirty` messages to the shell and consumes shell-level DFM save commands before forwarding them to the active floating DFM iframe. New floating windows start clean until their iframe reports an actual edit state.
- Floating DFM window active state is tracked by DFM iframe edit/history/tab messages and reported to the shell with `arcrho:project-instance-dfm-active-state`; Project Instance forwards `arcrho:assistant-context-request`, `arcrho:dfm-apply-method-payload`, `arcrho:assistant-dfm-edit-approval`, `arcrho:assistant-apply-json-edit`, `arcrho:assistant-revert-json-edit`, and nested `arcrho:open-path` requests so macros, ArcBot approval review, and file-open actions can use the same active-context and desktop-open contracts for standalone and nested DFM pages. ArcBot app context uses the top active non-minimized floating Dataset/DFM window as the primary Project Instance context and includes lightweight metadata for the other visible nested windows so ArcBot knows they are open without eagerly loading every window's data. The App Context hover text shows the Project, Segment, active nested tab name, table-consistent Method Type, and visible nested-tab count. Minimized nested windows are excluded from ArcBot app context.
- Nested Dataset, DFM, Result Selection, Bornhuetter Ferguson, and Cape Cod windows render dirty-close confirmation inside their own page iframe through the shared close-confirm component; Project Instance only invokes each child page's close hook and does not relay or render the modal.
- Project Instance handles the shell `arcrho:automation-open-dataset` message for Python UI automation. The command opens or activates a floating Dataset Viewer window for the current selected reserving-class path, or opens the matching DFM/Result Selection/Bornhuetter Ferguson/Cape Cod method window when callers pass `openMethod` with a method type, then returns the project name, selected path, dataset name, window id, title, and current window properties to the command bridge.

The command reloads the selected reserving-class dataset table from disk with the same behavior as the refresh toolbar button, then returns the project name, selected path, and `refreshed` status to the command bridge.
- Project Instance handles the shell `arcrho:automation-window-command` message for Python UI automation window objects. - Left and right panels own their scroll areas so overflowing path trees and dataset tables scroll inside the project instance tab frame.
